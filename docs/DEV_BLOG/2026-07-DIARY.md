# July 2026 Development Diary

## Overview

GeneralsOnline friends-scale integration and cross-platform multiplayer work.

## 2026-07-13 — Physical iPad online entry

- Replaced the Android bootstrap with a full GeneralsXZH ARM64 shared-library
  build selectable through `build-android-zh.sh --full`. The Android entry now
  uses app-private `files/GameData`, captures native stderr there, and has an
  ADB streaming provisioner for user-owned retail archives, fonts, current
  menu data, and writable defaults without placing large assets in the APK.
- Reached the first full-engine Android graphics milestone on the Pixel 7
  emulator. DXVK now treats unsupported robustness2 features as optional,
  selects D16 before initial device creation to avoid Android surface reuse,
  and exposes the native display mode without relying on the desktop DXVK mode
  descriptor. Zero Hour parsed the retail data and rendered its main menu.
- Diagnosed the subsequent animated-render crash from its ARM64 instruction and
  fault value. DXVK's imported swapchain-resource paths accessed the shared
  allocation-object pool without the allocator mutex, allowing a live imported
  object (`refcount=1`, `Imported`) to remain as the free-list head. Serialized
  both import paths and corrected their resource-cookie assignment. The rebuilt
  APK then rendered and ran a mission for over 11 in-game minutes with terrain,
  units, particles, HUD, and pause menu, with no repeat of the allocator crash.
  Android GFXStream also returned `VK_SUBOPTIMAL_KHR` perpetually for the same
  fixed-size surface; accepting that usable status on Android stopped DXVK from
  rebuilding an identical five-image swapchain every frame while preserving
  recreation for out-of-date surfaces and real failures. The rebuilt runtime
  log verifies stable presentation. Audio, movies, saves, touch controls, and
  online cross-play remain to be validated.
- Provisioned the iPad's GeneralsOnline credentials and persistent self-hosted
  service URL, then verified that authentication reaches the Online welcome
  screen on the physical device.
- Symbolicated the Quick Match crash to the legacy
  `TheGameSpyInfo->registerTextWindow()` call. Quick Match and Communicator are
  outside the friends-scale custom-match MVP, so GeneralsOnline builds now keep
  those buttons and the Personal Info overlay disabled while preserving Custom
  Match and legacy GameSpy behavior. Added explicit post-MVP plan items to port
  and re-enable all three features once their NGMP paths are tested.
- Began the physical Mac↔iPad Custom Match test. The iPad discovered the Mac
  lobby but correctly reported a version mismatch: Apple clients hashed their
  entire platform-specific executable into `exe_crc`, so macOS and iOS could
  never agree. GeneralsOnline builds now use the shared version plus multiplayer
  scripts as their platform-neutral executable compatibility hash; `ini_crc`
  remains the gameplay-data guard.
- Completed the first physical Mac↔iPad GeneralsOnline match over LAN after
  deploying the compatibility-hash fix to both clients. The iPad joined the
  Mac-hosted custom lobby, both players readied and started, GameNetworkingSockets
  established the direct ICE peer connection, gameplay remained synchronized,
  and the match ended normally. The host log recorded the iPad peer disconnecting
  gracefully with no crash or desync, proving the full Apple↔Apple match path.
- Reordered the next portability phase because physical Windows/Linux hardware
  is temporarily unavailable. Android ARM64 now follows Apple↔Apple: first an
  NDK/SDL3 APK and emulator boot, then Android↔Mac/iPad GeneralsOnline play.
  Windows/Linux x86-64 and ARM↔x86 determinism remain planned immediately after
  the Android phase rather than being removed from scope.
- Established the first Android ARM64 executable milestone. Added an API 35
  Gradle application using NDK r28c and SDL 3.4.2's official Android
  AAR/Prefab package, with a Vulkan 1.3 manifest requirement, landscape SDL
  Activity, pinned Gradle wrapper, checksum-verified dependency fetcher, and
  one-command build/install scripts. The debug APK built and signed, installed
  on the ARM64 Pixel 7 emulator, loaded `libmain.so`, entered `SDL_main`, and
  rendered the verified 2400×1080 bootstrap canvas without a crash. This proves
  the Android Activity/Java, APK, ARM64 NDK, SDL event loop, and renderer chain;
  the next gate is replacing the bootstrap with the full Zero Hour engine and
  an Android DXVK native build. Android Back was also injected through `adb`;
  SDL delivered it to the native loop, which returned normally before the
  Activity completed pause, surface destruction, stop, and destroy callbacks.
- Completed the Android DXVK-native gate. Added a reproducible NDK r28c/API 35
  ARM64 Meson cross configuration, isolated SDL3 AAR pkg-config metadata, and
  build/staging scripts for D3D8 and D3D9. Fixed MoltenVK portability-subset
  code so beta-only types remain Apple-only, and taught the SDL3 WSI to load
  Android's unversioned `libSDL3.so` soname. Both libraries now compile and are
  packaged in the APK. On the Pixel 7 emulator, SDL created a Vulkan 1.3
  instance plus `VK_KHR_android_surface`, and `Direct3DCreate8` successfully
  initialized DXVK's Android Vulkan adapter path. The bootstrap remains alive
  afterward; the next graphics gate is a real D3D8 device/swapchain through
  the full Zero Hour target.

## 2026-07-12 — GeneralsOnline server connection test

- Added a Test Connection action beside the persistent GeneralsOnline server
  address in Extra Options.
- The action validates the typed URL, probes the backend `ServiceConfig`
  endpoint without saving, uses a five-second timeout, and distinguishes HTTP
  failures from network, TLS, firewall, and local-network failures.
- The control is hidden when `SAGE_GENERALS_ONLINE` is disabled, prevents
  duplicate requests while a test is pending, and the macOS GeneralsXZH build
  passes. Physical-device and in-game feedback validation remains.
- Continued into iOS lifecycle handling: background events now release NGMP's
  live curl WebSocket before process suspension, while foreground events enter
  the existing authenticated reconnect path. A narrow bridge keeps NGMP
  headers out of the SDL platform layer. Both macOS and ARM64 iOS builds pass;
  device app-switcher validation remains.
- Audited the planned `IP_BOUND_IF` concern: it applies only to legacy LAN
  `UDPTransport`; GeneralsOnline uses GameNetworkingSockets through
  `NextGenTransport`, so no NGMP interface-binding change is needed. Updated
  the iOS Local Network prompt to cover self-hosted servers and peer traffic.
- A signed dev-package attempt is blocked by host setup: CoreDevice is
  unavailable and this Mac currently has no valid Apple Development signing
  identity. The unsigned ARM64 iOS engine build remains green.
- Added `setup-install-ios-zh.sh`, a guided one-command workflow that checks
  Xcode and signing, verifies a connected device, configures GeneralsOnline,
  builds ARM64 iOS, and invokes the existing package/install pipeline. It uses
  the documented local Team/Bundle values by default and gives focused recovery
  instructions when certificate, CoreDevice, device trust, or MoltenVK setup is
  missing.
- Fixed device discovery for current CoreDevice output, which reports a trusted
  iPad as `available (paired)` rather than the older `connected` state.
- Fixed the guided installer to auto-detect and export the installed LunarG
  `VULKAN_SDK` platform directory before CMake configuration. Without it, preset
  expansion silently cached `/lib/MoltenVK.xcframework/...` and failed at link.
- Fixed the iOS Extras entry point after device testing found it invisible: the
  runtime-created button now has explicit cross-renderer colors and borders.
  Full packages also overlay the repository's current `ExtrasMenu.wnd`, instead
  of retaining a stale staged copy that lacked Test Connection.
- The device screenshot showed the dynamic control clipped into Display Options
  over the Brightness slider, and confirmed this retail WND has no Keyboard
  Options button. The final iOS entry therefore reuses the guaranteed visible
  bottom-left Defaults button as Extras; desktop layouts remain unchanged.
- Pulled and symbolicated the physical iPad crash report after opening Extras.
  It identified a null-token read in `parseDrawData`; the three new WND controls
  used abbreviated draw-state lists. Expanded every enabled/disabled/hilite
  record to the legacy parser's fixed nine entries.
- Diagnosed the follow-up device crash in `W3DGadgetHorizontalSliderImageDraw`:
  all five Extra Options sliders supplied `NoImage` for the two disabled-state
  images that the legacy renderer unconditionally uses as its filled and empty
  track segments. Assigned valid `MainMenuRuler` images to both slots.
- Pulled the third device crash, which advanced to
  `W3DGadgetTextEntryImageDraw`. The server-address field incorrectly selected
  the four-image renderer despite defining only colors. Switched it to the
  standard color renderer and made the shared image renderer fall back safely
  when any required artwork is absent.
- Physical-device validation then reached the complete menu and exposed a
  consistent rendering-mode error: its background, sliders, and buttons all
  selected image rendering while defining color-only `NoImage` states. Moved
  those controls to the standard color renderers, restoring the opaque menu
  panel, full slider tracks, and visible button surfaces.
- A layout correction briefly misread WND `SCREENRECT` fields as position and
  size. Device output and `parseScreenRect` confirmed they are true upper-left
  and bottom-right coordinates. Restored valid rectangles, retained narrower
  color-slider tracks, and made the menu root fully opaque.
- Fixed non-responsive Extra Options actions: the four pushbuttons were using
  the parent menu callback directly instead of forwarding their selection
  messages to it. Apply, Defaults, Back, and Test Connection now use
  `PassSelectedButtonsToParentSystem`.
- Fixed the iOS software keyboard covering SAGE entry fields. The SDL platform
  loop now supplies `SDL_SetTextInputArea` with the focused gadget's screen
  rectangle before starting text input, allowing UIKit to shift the game view
  just enough to keep the active field visible; the area is cleared on blur.
- Device validation showed SAGE's text rectangle was still in render-resolution
  pixels while UIKit consumes SDL window coordinates, producing excessive view
  movement. Added per-axis conversion using the SDL window and display sizes.
- Increased the GeneralsOnline address entry font from 10 to 18 points after
  physical-device testing showed typed text was unnecessarily small relative
  to the iOS field and keyboard.
- Seeded an unsaved iOS configuration with the current LAN service endpoint,
  `http://192.168.1.140:9000/env/prod/contract/1`; the Defaults action restores
  it on iOS while existing persisted addresses continue to take priority.
- Corrected the iOS seed condition: GeneralsOnline initializes its raw setting
  to the localhost default rather than an empty string, so both localhost forms
  are now treated as unsaved defaults and replaced in the iOS field.
- Fixed the actual address-field data failure: its WND record replaced
  `GadgetTextEntrySystem` with the button-message forwarding callback, preventing
  both `GEM_SET_TEXT` and `GEM_GET_TEXT`. Restored the text-entry system callback,
  so the default renders and validation receives the typed URL.
- Fixed touch actions remaining inert by explicitly assigning the registered
  gadget input callbacks in the custom WND instead of `[None]`: pushbuttons,
  horizontal sliders, and the text entry now receive their normal input paths
  regardless of loader initialization order.
- Fixed Apply, Defaults, and Back retaining invalid IDs. They were initialized
  only from the menu's `GWM_CREATE` handler, but the WND callback is installed
  after that event. Their name keys now initialize in `ExtrasMenuInit`, alongside
  every other control ID.
- After device input still failed, removed the remaining dependency on WND
  parser ordering: `ExtrasMenuInit` now explicitly assigns the menu root as
  each button's owner and binds the canonical pushbutton input/system handlers
  at runtime, including Test Connection.
- Replaced the still-failing owner-forwarding hop with a dedicated runtime
  button-system bridge. Each custom button targets itself; selection messages
  invoke `ExtrasMenuSystem` directly, while all other messages retain canonical
  `GadgetPushButtonSystem` lifecycle behavior.
- Captured a persistent four-stage physical-device input trace after console
  output proved unavailable at runtime. It confirmed the iPad tap reached touch
  translation, pushbutton down/up, `GBM_SELECTED`, and `ExtrasMenuSystem`.
- Fixed the proven lifecycle failure: `ExtrasMenuShutdown` cleaned up its state
  but never notified `TheShell` that shutdown had completed. Back and Apply now
  hide the layout and call `shutdownComplete`, allowing the pending shell pop to
  remove Extra Options and restore the Options screen.
- Added an iOS three-finger Escape gesture for long movies and cutscenes. The
  third touch cancels the active two-finger pan and injects an SDL Escape
  down/up pair through `SDL3Keyboard`, which is also polled by the movie-abort
  loop; all remaining fingers are swallowed until lifted.
- Added a physical-iOS GeneralsOnline account provisioning script. It reads the
  backend JWT key from the gitignored `.env`, mints the selected pre-seeded
  account's refresh token, writes a permission-restricted temporary credentials
  file, copies it into the app's private data container, removes the temporary
  secret, and relaunches the app. Defaults target account `34621 / nathan` and
  the current GeneralsXZH bundle, with explicit account/device/bundle overrides.
