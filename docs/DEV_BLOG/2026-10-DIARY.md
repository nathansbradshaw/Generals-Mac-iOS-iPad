# October 2026 Development Diary

## Overview

## 2026-10-08 — Native replay test jobs

- Prepared explicit Linux x86_64 and Windows x86 replay jobs. Windows uses the
  existing Win32/DirectX8 build path, not the unfinished 64-bit SDL3 port.
- Inputs are encrypted and fetched from a draft release; the key is an Actions
  secret. Source edits, retail game data, accounts, and saves are not committed
  with the CI bootstrap. Accounts and saves are excluded from the test payload.
- Replay success requires recorded completion and exact agreement with all
  populated-world reference samples. Diagnostics are encrypted before upload.
- The first jobs reached GitHub but the read-only token could not list the
  draft input. A broader token permission was rejected before push. The
  known asset ID also remained inaccessible to the read-only job. The final
  download uses an expiring URL scoped only to the encrypted asset, passed
  through a masked secret; the repository token remains read-only.
  Checkout does not persist the token.
- Both runners downloaded and decrypted the ciphertext successfully. Windows
  configuration exposed PowerShell splitting the decimal CMake policy argument;
  quoted the argument before rerunning. Windows then exposed stale game-local input source paths. Build repairs are
  passed through a small encrypted overlay secret; the private source remains
  unpublished. Commits marked `[windows-only]` retry just Windows while the
  independent Linux baseline continues. The first Windows compilation exposed
  the Linux multimedia shim shadowing the SDK; moved it to a non-Windows include
  directory in the encrypted source overlay. Native Linux completed the full replay with 22/22 exact populated samples.
  Windows profiling helpers needed native thread-ID guards. The overlay is
  now a small encrypted patch checked against the exact input snapshot, and
  Ninja collects independent Windows compiler errors in one pass. Windows
  build/replay results remain pending. Live networking, rendering, input,
  physical hardware behavior, and the modern Windows port remain unverified.
